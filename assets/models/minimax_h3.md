# MiniMax 系列（默认核心系列）

`minimax_h3`

## 这条系列怎么写

这个系列**没有 `workflow` 字段**：图在渲染时按你的声明现场组装。你写的是「这一镜要什么」——选一个 `head`，配 `references` 与 `guides`——不写「怎么接线」。写了 `workflow` 会被当场挡下。

### 逐镜头参数

`positive`、`width`、`height`、`length_frames`、`fps`、`seed`。

**这条系列不吃、写了会被挡下**：`negative`、`duration_seconds`。提交提示词包时会按这张表对账，写了它不吃的参数直接报 `schema_violation`，不会等到渲染才发现。

### head：这一镜怎么起幅

| head | 可用 | 用来做什么 | 参考槽位 | 首尾帧 | preview 步数 |
|---|---|---|---|---|---|
| `reference` | 是 | 挂参考锁身份与风格，起幅由模型定。绝大多数镜头用它。 | image × 9、video × 3、audio × 3 | — | 4 |
| `image` | 是 | 给首尾帧，锁构图与运动轨迹。要精确控制起幅落幅时用它。 | —（不接参考） | `first_frame`、`last_frame` | 8 |

划掉的介质说明那条输入通道还没在真机上跑通过一整镜，写了会被结构化阻塞——不是「以后会生效」，是现在选不了。

### guides：把素材锚在某一帧

| kind | 可用 | 做什么 |
|---|---|---|
| `image` | 是 | 把一张图锚在某一帧。接续上一镜就用它锚 `<上一镜>.tail`（尾帧） |
| `clip` | 是 | 把一段帧序列锚在某一帧，比单帧接得更稳。写 `<上一镜>.tail5` 这种带帧数的——**锚点必须短于这一镜**，等长的会把整镜钉死 |
| `audio` | 是 | 把一段音频锚在某一帧。实测**影响的是整镜的声音**，不只锚定那一刻——拿它给这一镜的声音定调，不要指望它精确对齐到某一帧 |

`at_frame` 负数从末尾倒数，`-1` 是最后一帧。`head: image` 只有首尾两个槽位，锚不了中间帧。

### 帧数与画幅

`length_frames` 吃 **17k+5** 的网格：5 / 22 / 39 / 56 / 73 …（k ≥ 0）。写别的值模型会自己 snap 到最近的合法值，**于是成片时长跟你声明的对不上**——而后期拼接是按声明算的，差出来的部分会一路错到交付。提交时会当场挡下并给出最近的两个合法值。

按目标时长反推：`length_frames ≈ 秒数 × fps`，再挪到最近的网格值上，然后用挪完的帧数回头修剧本里那一拍的时长，别让两边对不上。

`width` / `height` 取 32 的倍数，短边不超过原生画布 768。超出的部分不会带来细节，只是更慢；要更高分辨率走后期的超分。

## 提示词公式

```
[运镜指令] 主体 + 可见动作 + 场景 + 光线/质感 + 连续性约束
```

一条提示词只描述**一个可读镜头**：一个清晰主体、一个可见动作、
一个受控环境、一个有意图的运镜。**句首放最重要的视觉元素**——
开头几个词的权重最高。

正向提示词上限 2000 字符，但写满不是目标。

## 运镜指令

运镜写成方括号指令，放在**句首**。分镜里的 `camera_motion` 与指令
一一对应，照下表翻译，不要自己造词：

| 分镜的 `camera_motion` | 提示词里写 | 说明 |
|---|---|---|
| `static` | `[Static shot]` | 固定机位 |
| `push_in` | `[Push in]` | 推近（机身前移） |
| `pull_out` | `[Pull out]` | 拉远（机身后移） |
| `pan_left` | `[Pan left]` | 左摇 |
| `pan_right` | `[Pan right]` | 右摇 |
| `tilt_up` | `[Tilt up]` | 上仰 |
| `tilt_down` | `[Tilt down]` | 下俯 |
| `truck_left` | `[Truck left]` | 左移（机身平移） |
| `truck_right` | `[Truck right]` | 右移（机身平移） |
| `pedestal_up` | `[Pedestal up]` | 升镜（机身抬高） |
| `pedestal_down` | `[Pedestal down]` | 降镜（机身降低） |
| `zoom_in` | `[Zoom in]` | 变焦推近（镜头组变焦） |
| `zoom_out` | `[Zoom out]` | 变焦拉远 |
| `tracking` | `[Tracking shot]` | 跟移 |
| `handheld_shake` | `[Shake]` | 手持晃动 |

官方建议一次组合不超过三个指令；分镜每镜只允许一个主运动，
所以正常路径上永远只用一个。

## 这条系列没有负向提示词

**不要写 `negative`。** 这个系列的基线没有绑定这个参数。
提交提示词包时会按能力面对账，写了它直接报 `schema_violation`——
不会等到渲染完才发现自己什么都没控制住。

约束要改写成正向提示词里的**完整句子**：

| 想禁止的 | 写成 |
|---|---|
| 画面里出现文字/水印 | 画面中不出现任何文字、标志或水印 |
| 中途切换场景 | 一镜到底，不切场景 |
| 主体跑出画框 | 人物保持在画面中央 |
| 多余的人 | 画面中只有一个人 |
| 镜头乱动 | 固定机位，镜头不移动 |

完整句子比 `no text, no watermark` 这种词堆可靠得多。

## 音频

这是**音视频联合生成**模型——它会同时出声音。`audio` 字段留空等于
放弃这个能力，换来一段哑片。

写清三层：环境声、拟音、人声/音乐。有对白就放引号里并注明语言。

## 一致性

跨镜一致性有两条腿，**两条都要用**：

1. **挂参考**。`head: reference` 的镜头把角色卡、场景卡挂进 `references`，
   模型看的是实物，比读文字描述准得多。上限见上面的表。
2. **逐字复用身份锁**。每一镜的提示词都要原样带上那段外观描述，
   不要写「同一位女孩」——对模型来说每一镜都是第一镜，指代没有对象。

参考解决「像不像同一个人」，身份锁解决「模型有没有被告知要像谁」。
少任何一条，角色都会在第三镜变成另一个人。

镜头之间接不接得住是第三件事，靠 `guides` 锚上一镜的尾段，
见 `.agents/doctrine/assembly/shots.md`。

## 一份写好的提示词长什么样

> 船头切开清透湖面，一位20岁东亚女性，长黑发及胸，白色无袖连衣裙，
> 低帮白色板鞋，奶油色小斜挎包，以约30度侧脸快速入画并转头露出笑容。
> 船行的风把碎发吹到她嘴角，她抬手把碎发别到耳后。层叠群岛与远山在后景。
> 上午冷白自然光，柔光顺照，低对比。镜头缓慢前推。一镜到底，不切场景，
> 人物保持在画面中央，画面中不出现任何文字、标志或水印。

拆开看：主体和动作在前，三个物理事实（风吹碎发、抬手别发、船切水面）
都落到了具体的可见动作上，光写成了光源+光型+对比度，最后是四条正向的
连续性约束。全程没有一个「电影感」「唯美」这类对模型无效的词。
