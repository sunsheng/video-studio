# 结构与节奏

## 拍点类型怎么用

`beat_type` 的六种取值是一副骨架，不是必须凑齐的清单：

| 类型 | 这一拍在做什么 | 典型位置 |
|---|---|---|
| `hook` | 勾住——给一个不看下去会难受的理由 | 开头，必须有 |
| `setup` | 交代——谁、在哪、什么状态 | 钩子之后 |
| `develop` | 推进——信息量最大的地方 | 中段 |
| `turn` | 转折——观众的预期被改写 | 中后段 |
| `payoff` | 兑现——前面埋的东西在这里结算 | 后段 |
| `resolve` | 收束——给一个能停住的画面 | 结尾 |

十秒的片子塞不下六种。常见的可用骨架：

- **十秒五镜**：`hook` → `setup` → `develop` → `payoff` → `resolve`
- **十五秒有转折**：`hook` → `setup` → `develop` → `turn` → `payoff`
- **三十秒**：可以有两个 `develop`，或者 `turn` 之后再给一个 `develop`

**每一拍都要能说出自己是哪一种。** 说不出，通常意味着这一拍在重复上一拍。

## 时长按内容分配，不平均切

平均切分是最容易被看出来的偷懒。十秒五镜切成每镜两秒，观众感觉像幻灯片，
因为**动作的完成时间跟镜头没关系**——一个转头 0.8 秒够了，一个从抬手到
按下快门的完整动作 2.4 秒都嫌紧。

分配的依据，按优先级：

1. **动作完成度**：这个动作从起到收需要多久？不够就会看到动作被切断。
2. **信息量**：观众需要多久才能看清画面里的新信息？陌生的空间要更久。
3. **情绪停留**：需要观众"感受一下"的画面要留出停顿；推进型的镜头不要。

写进 `timing_rule` 的必须是依据，不是重复结果。
「按内容分配」是废话，「第三镜要完成抬手、摇镜、按快门三个动作，
所以给 2.4 秒，是五镜里最长的」才是依据。

**总时长必须精确合计。** 各拍之和 ≠ 总时长是最常见的退回原因，
提交前自己加一遍。分镜的镜头时长也要与剧本各拍对齐。

## 短视频的节奏模板

竖屏短视频的观众用拇指投票，节奏是**递进的**，不是均匀的：

```
长 → 短 → 短 → 停 → 击
```

开头可以稍长（要建立空间），中间越来越短（推进），
在关键点前**留一个停顿**（给观众预期的时间），然后落下。

一分钟以上的分集内容另有一套模板：前 30 秒交代背景、困境、动机；
中间推进主线，台词要少而准；最后 30 秒留一个必须看下一集才能解决的悬念。

## 每一拍的自检

- 说得出 `beat_type` 吗？
- 这一拍删掉，故事还成立吗？成立就删。
- 时长是从动作和信息量推出来的，还是从「总时长除以拍数」来的？
- 它和上一拍在做同一件事吗？
