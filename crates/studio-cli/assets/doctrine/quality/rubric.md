# 内容验收

验收有两半，判的是两件不同的事。

| | 技术验收 | 内容验收 |
|---|---|---|
| 谁做 | 控制面 | 你 |
| 依据 | ffprobe 实测元数据 | 看片子 |
| 判什么 | 片子**完整**吗 | 片子**好**吗 |
| 结果 | 决定 `review.passed` | 不决定 passed |

技术验收全过，只说明时长对得上、画幅没错、音轨在、镜头数没少。
这些全对，片子仍然可以是五个互不相干的镜头拼在一起。
**从头到尾没有一处在问「这东西好不好看」**——内容验收补的就是这一处。

它不阻塞交付：片子已经出来了，你的评价改变不了它是否完整。
但不交这一份，这次交付就没有留下任何「照自己定的标准打了几分」的记录，
作品也就不算收尾。

## 五个维度

固定五条，不可增删。让你自选维度等于让你挑自己做得好的那几条。

| 维度 | 问自己 |
|---|---|
| `hook` | 观众在第几秒已经知道这是什么、值不值得看下去？超过 3 秒就是没有钩子 |
| `information_density` | 删掉哪一镜观众也不会察觉？那一镜就没有信息 |
| `pacing` | 动作复杂的镜头有没有被切太短？空镜有没有拖？ |
| `consistency` | 同一个人、同一个地方跨镜有没有变？这是 AI 视频最先露馅的地方 |
| `brief_metrics` | brief 里那些**内容型**的 success_metrics，逐条兑现了没有？ |

## 每条都要有时间点

没有时间点的自评是「我觉得还行」。

写了 `at_seconds: 5.8` 就得真去看那一帧——说不出那一刻画面里有什么，
就写不出证据。这条要求不是形式主义，它是逼你**真的看一遍**的唯一办法。

`evidence` 写在那个时间点上**看见/听见**了什么，以及它为什么支持这个结论：

> ✅ `at_seconds: 5.8` — 第四镜的碰杯除了「她很开心」没有给出新信息，
>   删掉它观众不会察觉少了什么
>
> ❌ `at_seconds: 5.8` — 这一镜还行

## 说实话比说好话有用

`not_met` 和 `partially_met` 不会让这次交付失败——技术验收已经过了，
片子该交还是交。写 `met` 也不会给你加分。

这份记录唯一的用处是**下一次**：哪个维度反复不达标，就该回头改
方法层的哪一份文档。全写 `met` 的自评等于什么都没写，
既骗不到人，也帮不到下一次。

最有价值的一条通常是那条 `not_met`。

## `summary` 写什么

一句话：**最强的一点**和**最弱的一点**。

不是复述五条结论——那五条就在旁边。是把「这片子成在哪、差在哪」
各说一句，让人不看明细也知道这次交付的形状。
