# ADR-0003：作品级决定档案，追加即历史

## 背景

`studio.revise(stage, message)` 的 `message` 是用户唯一一条能直接传到
Agent 手里的原话——「不要固定 2 秒，要根据镜头内容智能分配」这类。
它现在**用完即弃**：只影响当次重做，重做完就没了。

后果是同一部作品里，用户可能要在剧本阶段说一次「不要平均切分」，
到了分镜阶段再说一次，因为 Agent 那时已经看不到前一次说过什么。
确认门上选了哪个方案也一样：`answer` 只把选择写进那个阶段自己的产物
（`_gate_choice`），横向不可见——第五个阶段不知道第二个阶段用户挑的是
「先藏后露」还是「跟着她走」。

这是「越用越准」缺的那一环：系统记得**做过什么**（timeline、产物），
不记得用户**要什么**。

## 决策

作品级维护一份**决定档案**，由控制面记录，在 `next_action.decisions`
里回给 Agent。

两个来源，都是控制面已经看见的东西，不需要 Agent 额外汇报：

| 来源 | 记什么 | kind |
|---|---|---|
| `studio.revise(stage, message)` | 用户的原话，逐字 | `rejected` |
| `studio.answer(qid, option)` | 用户选中的那个选项的标签 | `chose` |

不引入第三个来源。让 Agent 自己往档案里写「我总结出用户喜欢 X」是
诱人的，但那是**它的推断**，不是用户说过的话——一旦推错，错误会被
当成事实反复注入，而且没有任何人有机会纠正它。档案里只放用户
**实际说过、实际点过**的东西。

### 追加即历史：不删、不改、不因 undo 回退

档案是**历史**，不是状态。已经记下的条目永不修改、永不删除，
`studio.undo` 也不回退它。

理由：`undo` 恢复的是阶段产物，不是「用户没说过那句话」。用户说过
「不要固定 2 秒」，然后撤销了那次修订，这不等于他改了口味——多半是
他发现撤销更省事。真要改口味，他会再说一句新的，那句自然成为更新
的一条。

所以档案按时间倒序给出，**后面的条目在同一件事上压过前面的**。
这条规则要写进 AGENTS.md，因为它决定了 Agent 该怎么读这份档案。

同一个理由下，timeline 里的 `revised` 事件本来也不因 undo 消失——
两者的语义在这里是一致的，不需要额外解释。

### 有上限，因为上下文有上限

只回最近 20 条。整套提示词架构的原则是渐进披露（默认不加载、用到才
读），决定档案是**默认就注入**的少数东西之一，所以它必须有硬上限。
一部十镜头的片子走完全程大约产生 6–10 条，20 条留了一倍余量；
真的超了，说明这部作品改了非常多轮，那时最旧的那几条也确实过时了。

### 作品级，不跨作品

档案存在 bundle 自己的 `.studio/studio.db` 里，`cp -r` 跟着走，
`rm -rf` 跟着没——与 ADR-0001「一个文件夹就是一部作品」一致。

不做全局的用户口味库。跨作品的口味听起来更值钱，但它需要一个中央
存储，而中央存储正是 ADR-0001 花力气消掉的东西；何况「上一部片子
不要平均切分」对这一部未必成立——那是另一个题材、另一个受众。

## 存储

新表，追加写：

```sql
CREATE TABLE IF NOT EXISTS decisions (
    id     INTEGER PRIMARY KEY AUTOINCREMENT,
    at     TEXT NOT NULL,
    stage  TEXT NOT NULL,
    kind   TEXT NOT NULL,   -- rejected | chose
    detail TEXT NOT NULL
);
```

`IF NOT EXISTS` 在 `Store::open` 里执行，所以**老 bundle 用新程序打开
时自动补上这张表**，不需要迁移脚本、不需要版本号跳变。这张表不进
完整性摘要（摘要覆盖 stages 与 questions）：档案是追加型历史，外部
篡改它不会让状态机走到不一致的地方。

## 后果

- Agent 每次拿 `next_action` 都能看到用户此前否决过什么、选过什么，
  不必翻 timeline，也不必指望上下文没被压缩掉。
- 用户在剧本阶段说过的话，在分镜、提示词阶段仍然有效——这正是原来
  最容易丢的一环。
- 档案会越来越长。上限 20 条是硬的；到那之后最旧的自然滚出去。
- 这是本次提示词架构重构里**唯一动了状态存储**的改动。其余改动
  （词表、方法层、能力面、质量闸、内容验收）都不需要新表。
